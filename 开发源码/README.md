# 值班系统开发说明

## 项目

| 目录 | 职责 |
| --- | --- |
| `src/Duty.Core` | 不可变个人填报、编码协议、规则检查、人工调整校验和内存撤销 |
| `src/Duty.Solver` | OR-Tools CP-SAT分层求解与草案 |
| `src/Duty.UI` | WPF主题、两种可取消标记、特殊班同步、排班拖放和可迁移性检查 |
| `src/Duty.Intake` | 独立意愿填写程序 |
| `src/Duty.Scheduler` | 独立收集、排班、人工调整、导出程序 |
| `src/Duty.Excel` | 使用空白模板进行结构化OOXML填表，不增加工作表 |
| `tests/Duty.Tests` | 编码、求解、穷举对照及人工操作的独立控制台测试 |
| `tools` | 构建、独立校验、原生依赖分析和便携迁移验收 |

程序不预设人员名单，启动时没有姓名或填报记录。公开测试和手册截图仅使用虚构示例，不包含实际人员的数据。

填写界面只有“优先安排”和“不可安排”两种标记，重复点击相同标记会恢复未标记的可排状态，换标记后直接覆盖。普通格默认可排；特殊班保留单独报名，默认显式禁排。一次拖刷固定为标记或清除，行列批量操作在全部已有相同标记时清除。`PreferenceMarks`集中定义默认值及单格转换。内部三态值及PB1协议不变，旧代码仍按原始选择解码，不重新解释为新默认值。

## 构建

开发构建脚本需要PowerShell 7与.NET 10 SDK。用户运行发布程序不需要安装PowerShell 7、SDK或系统.NET。

```powershell
.\tools\build.ps1
dotnet run --project .\tests\Duty.Tests\Duty.Tests.csproj -c Release
.\tools\verify-portable.ps1
```

重复便携验收时可使用新的标签，例如 `.\tools\verify-portable.ps1 -RunLabel review_20261023`，保留已有测试副本和证据。独立校验命令为 `python .\tools\verify-independent.py <项目根目录> [本轮导出文件路径]`。

`build.ps1`以自包含`win-x64`目录发布两个程序，不启用裁剪，不依赖程序所在位置的绝对路径，并分析所需MSVC导入，为求解器补齐本地运行库。

`assets/licenses`保留已收集的运行时和上游许可原文，构建时复制到相应程序目录，不要求用户运行联网脚本。`tools/collect-licenses.ps1`仅在开发维护许可资料时运行。正式对外发布前的MSVC再分发与原生传递性依赖复核边界见许可说明。

便携验证脚本将目录复制到中文和空格混合的新路径，清除PATH中的开发工具位置，把DOTNET_ROOT设为不存在的目录，再直接启动EXE执行界面、求解和导出检查。已存在的迁移测试目录不会被脚本自动删除。

已经提供空白模板`../排班系统/排班模板.xlsx`。程序运行时不需要Node.js，导出只用标准库结构化修改模板。公开目录不附带原始验收截图、日志或生成的排班结果。

图文操作说明见项目根目录`README.md`，配图在`docs/images`。重新制作时，先运行`tools/Duty.ManualCapture`生成虚构数据的界面截图到`qa/使用说明/原始截图`，再用Python运行`tools/build-readme-images.py`。只需额外安装`Pillow`，它不是运行软件的依赖。

## 填报码协议 PB1

展示格式为`PB1-`加无填充的RFC 4648 Base32，正文每8个字符分组。解码接受小写和ASCII空白，移除分组横线后严格检查有效字符、长度与规范尾部位。

| 字节位置 | 内容 |
| --- | --- |
| 0 | 姓名UTF-8字节数L，1字节 |
| 1 | 选项：bit0表示4节（0表示3节）；bit1表示特殊班；其他位必须为0 |
| 2至6 | 5天各1字节，每天四节按高位到低位，每格2bit：00禁排、01可排、10优先、11非法 |
| 7至6+L | 姓名UTF-8原文 |
| 最后4字节 | 大端CRC32 |

CRC32覆盖ASCII前缀`PB1`与前面的全部有效载荷，不包括CRC32字段本身，使用`System.IO.Hashing.Crc32`。独立校验脚本使用Python标准库`zlib.crc32`与`base64.b32decode`核对。

姓名需要非空、没有控制字符，最多32个Unicode标量字符，前后空白被去除；特殊班标志必须与周二第四节非禁排状态一致。没有批次、日期、个人ID或修订号。

## 求解目标

正常方案：个人班量精确等于3或4、每人至少一节早一。在岗位容量、禁排和特殊班意愿限制内，依次：

```text
最大化优先安排数 H
固定H的已证最优值，最小化个人到岗天数之和 D
固定D的已证最优值，最小化每日连续班段数 B
```

午休不切断第二节与第三节。前一层未证明最优时停止进一步冻结，返回当前可行结果并说明未证最优。

确定无法满足正常要求时，草案先最大化满足早一的人数，再最大化总安排节数，随后按H、D、B优化。两类个人缺口分别显示，不能用草案掩盖未排够。超时未找到正常方案不等于已证明无解。
